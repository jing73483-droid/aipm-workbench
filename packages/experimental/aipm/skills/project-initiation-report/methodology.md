# 立项方法论参考

## 1. 立项要回答的决策

立项报告不是“完整介绍项目”，而是为资源决策压缩不确定性。核心判断为：

1. **用户是否愿意改变行为**：问题是否真实、频繁、强烈，现有替代是否有明显代价。
2. **组织是否值得投入**：是否符合战略或商业目标，机会窗口是否存在，预期价值是否可衡量。
3. **团队是否有能力交付**：技术、数据、合规、资源和协作约束是否可控。
4. **现在是否应该行动**：等待的代价、验证成本和可逆性如何。

任何一项出现不可接受的红线，都可否决项目；不要只看加权总分。

## 2. 从原始需求到问题定义

按以下顺序拆解：

1. 用户是谁；
2. 何时、何地、在完成什么任务；
3. 哪一步受阻；
4. 现在如何替代或凑合；
5. 替代方式带来什么时间、金钱、风险或体验代价；
6. 为什么连续追问，直到落到团队可改变的一层；
7. 删除句子中的功能名，检查是否仍能表达问题。

问题定义句式：

> [目标用户] 在 [具体场景/任务] 中，因为 [可观察阻碍] 无法 [期望进展]；目前通过 [替代方式] 处理，造成 [可量化或可观察代价]。

弱问题信号：

- 只有“用户想要某功能”；
- 只有领导、销售或竞品提出；
- 只有态度表达，没有实际行为；
- 问题范围无限大，团队无法影响；
- 方案已定，调研只用于证明方案正确。

## 3. 用户证据

### 证据强度

由强到弱通常为：

1. 真实行为、交易、日志、工单、流失和实验数据；
2. 对最近一次真实经历的访谈、现场观察；
3. 多个独立来源一致的具体原话；
4. 用户对未来行为的承诺；
5. 泛泛态度、偏好和“我会用”。

样本数量不设统一魔法数字。根据风险和分群决定：

- 探索阶段重在覆盖差异与发现模式；
- 定量判断必须说明总体、抽样、样本量和偏差；
- 高风险或不可逆决策需要更强证据；
- 关键分群不可被总体均值掩盖。

### 访谈原则

- 问最近发生过什么，不问“你觉得这个想法如何”。
- 追问具体时间、动作、替代、花费和后果。
- 区分礼貌性认可与真实付出。
- 每条结论配原话、行为或数字。
- 主动寻找不使用者、流失者、边缘用户和反例。

## 4. 竞品与机会

先写本次分析要支持的决策，再找四类对象：

- 直接竞品：相同用户、相同任务、相似方案；
- 间接竞品：相同需求、不同方案；
- 替代方案：用户当前如何完成任务；
- 潜在竞品：有渠道、数据、技术或生态能力进入者。

比较维度按决策选择，可包括：

- 用户与场景；
- 核心任务和完整旅程；
- 价值主张与差异化；
- 功能与体验；
- 商业模式与定价；
- 数据、模型、成本和能力边界；
- 渠道、品牌、生态与迁移成本；
- 用户好评、差评、流失和未满足需求。

竞品分析必须落到：

1. 做或不做；
2. 机会来自哪个用户、需求或场景；
3. 我们为何有资格进入；
4. 对手为何可能成功、我们为何可能失败。

差异化句式：

> 面向 [特定用户] 的 [特定场景]，他们最在乎 [关键价值]；现有方案因 [结构性原因] 难以满足，而我们拥有 [可验证优势]。

## 5. 第一阶段范围

### POC、原型、MVP

- **POC**：验证技术或 AI 能力能否达到最低门槛，主要供内部判断。
- **原型**：验证用户是否理解流程、价值和交互，不代表真实使用。
- **MVP**：用真实或足够接近真实的闭环验证用户行为和业务假设。

三者验证的问题不同，不要相互替代。

### MVP 取舍

1. 写下唯一或最核心的待验证假设；
2. 从用户完成闭环所需能力反推范围；
3. 将所有候选项分为：
   - 必须做；
   - 明确不做；
   - 后续再做；
4. 每个“必须做”都要能连回假设、痛点、风险或合规要求；
5. 为每个“不做”记录理由和重启条件。

MVP 应像能使用的滑板，而不是缺轮子的汽车。

## 6. 指标体系

每个指标写清：

- 指标名称与业务含义；
- 公式和统计口径；
- 当前基线；
- 目标值或方向；
- 观察窗口；
- 数据源与埋点状态；
- Owner；
- 与决策的关系。

指标分层：

1. **结果指标**：用户、业务或战略结果；
2. **过程指标**：关键旅程是否改善；
3. **质量/护栏指标**：准确性、安全、投诉、成本、延迟等；
4. **学习指标**：核心假设是否被证实。

没有历史基线时，不编造精确提升值。先定义建立基线的方法和何时回看。

## 7. 决策矩阵

### 默认维度

可从以下维度起步，再与用户确认增删和权重：

- 用户价值；
- 业务/战略价值；
- 证据可信度；
- 交付可行性；
- 时间窗口；
- 资源效率；
- 风险与可逆性；
- 组织能力匹配。

评分要求：

- 先定义每个分值的锚点，再评分；
- 每项分数都附证据或推理；
- 权重总和为 100%；
- 记录评分人和分歧；
- 同时保留红线否决项；
- 分数用于暴露取舍，不替代判断。

## 8. 资源与计划

至少覆盖：

- 核心团队与各角色投入；
- 现金支出和持续运营成本；
- 数据、模型、供应商和基础设施；
- 跨团队依赖与外部审批；
- 关键路径和资源瓶颈；
- 里程碑、阶段闸门和决策人；
- 降级路线与失败后的资产复用。

排期原则：

1. 先验证最危险、最便宜可验证的假设；
2. 先做规则、数据和评价基线，再做复杂能力；
3. 资源分阶段批准，不一次性承诺全部投入；
4. 按瓶颈排计划，让非瓶颈团队可并行推进；
5. 外部时间窗口必须说明来源和错过代价。

## 9. AI 项目专项

### 是否该用 AI

至少检查：

- 任务是否高频或重复；
- 质量是否可评价；
- 是否存在人力、规模或能力瓶颈；
- 非 AI 流程、规则或搜索方案是否更便宜可靠；
- AI 带来的价值是否大于概率性错误和运营成本。

### 评测设计

评测不只写“准确率”：

- 任务分解与每项门槛；
- 代表性样本、难例、边界样本和红线样本；
- 人工标准、标注一致性和仲裁机制；
- 总体与关键分群表现；
- 置信度、拒答和转人工策略；
- 离线到线上指标映射；
- 版本回归与漂移监控。

### 责任与兜底

将流程分给三类主体：

- AI：生成、识别、推荐或辅助判断；
- 规则：权限、硬约束、红线和确定性校验；
- 人：高风险决定、申诉、低置信度和异常处理。

对招聘、绩效、医疗、金融、认证、处罚等高风险决定，默认不把最终决定权交给未经充分验证和授权的 AI。

### 成本

至少测算：

- 单次调用成本；
- 单活跃用户月成本；
- 峰值并发和延迟；
- 存储、向量检索、语音/图像等附加成本；
- 人工复核和运营成本；
- 模型升级、供应商切换和故障降级。

## 10. 四种结论的证据要求

### 立项

- 核心问题和用户价值已被充分验证；
- 第一阶段假设、范围和成功门槛清晰；
- 资源、依赖、风险和责任人可执行；
- 无未处理的致命红线。

### 条件立项

- 方向基本成立；
- 存在明确、有限且可在阶段内解决的前置条件；
- 每个条件有 Owner、期限、通过门槛和失败动作；
- 在条件满足前限制投入和权限。

### 转向验证

- 核心假设仍不确定；
- 可通过低成本实验显著降低不确定性；
- 暂不批准完整开发和规模投入；
- 验证结束必须重新做 Go / Continue / Pivot / Stop 决策。

### 停止

- 问题不真实或价值不足；
- 无可行差异化或组织能力不匹配；
- 成本、合规或安全风险不可接受；
- 最小验证已失败且无合理转向；
- 记录未来重启所需的新证据或条件。
